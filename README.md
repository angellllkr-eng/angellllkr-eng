## Duplicate control

Repository names are not treated as architecture. Known duplicate candidates are explicitly routed toward one canonical implementation:

| Family | Canonical | Duplicate/retire candidate |
|---|---|---|
| Eve chat | `eve-chat-template` | `eve-chat-1` |
| Next.js boilerplate | `nextjs-boilerplate` | `nextjs1` |
| Hill Monarch | `hill-monarch-quiet-glade` | `hill-monarch-quiet-glade-project` |
| Chatbot | archived `chatbot` | archived `chatbot1` |
| Empty source placeholders | — | `source1`, `source2` |
| Empty MindReply placeholder | — | `mind-repl` |
| Empty Own placeholder | `own` | `Own1` |

These candidates are preserved until GitHub administration or verified migration permits final archive/delete. No production agent should use them as new roots.

Some similarly named repositories are intentionally separate because their architectures or provenance differ: `openmontage` / `openmontage-source-mirror`, `a11-k-multiverse` / `a11-k-multiverse-5d`, `own` / `own-agent`, and the ResellerPro pair.

## Branch standard

`main` is the canonical integration branch for active work.

Use short-lived branches only when needed:

- `feat/<scope>`
- `fix/<scope>`
- `ops/<scope>`
- `docs/<scope>`
- `reconcile/<scope>`
- `release/<version>`

No permanent `final`, `latest`, `new`, `copy`, `backup`, `ready`, or `production` branches.

Repositories still using `master` are migration candidates; `main` must be established and verified before repository-administration changes are made.

## Agent operating contract

**UNDERSTAND → PROTECT → EXECUTE → VERIFY → RECORD → HANDOFF → CONTINUE**

Every agent should:

1. Read `PERSONAL_ESTATE_REGISTRY.md` before creating a repository.
2. Find the canonical home before implementing functionality.
3. Inspect actual files, manifests, entrypoints, workflows and deployment bindings.
4. Prefer reversible changes and dedicated short-lived branches.
5. Never merge or delete based on repository names alone.
6. Verify runtime state before claiming live/production.
7. Record material estate changes in `agent-control-plane` / `estate-reconciliation`.
