## Duplicate-control policy

- Repository names are not treated as proof of duplication; contents and deployment dependencies are checked first.
- Canonical implementations are selected before consolidation.
- Legacy copies remain preserved until their dependencies and history are safely migrated.
- Archived repositories are not treated as active production systems.
- Secrets, credentials, private conversations, payment data, and customer data never enter public repositories.
- Default branch and CI conventions are standardized where the connected administration surface permits it.

## Operating standard

**Evidence before claims.** Repository and deployment status is recorded as verified, ready, blocked, failed, or unverified — never guessed.

**Reversible by default.** Consolidation preserves history and avoids destructive changes until dependencies are understood.

**Clean by construction.** No duplicate production roots, no random forks, and no deployment from legacy repositories.
