## The estate

A deliberately smaller, cleaner GitHub surface is being established around **functional ownership**, not repository-name accumulation.

```text
A.K. ENGINEERING ESTATE
│
├── MINDREPLY       execution · operating platform · services
```

## Presentation standard

Every retained project should have:

- one clear purpose
- one canonical owner/home
- one understandable README
- explicit runtime and deployment ownership
- `skills/` for repeatable agent/operator capabilities where appropriate
- `tools/` for deterministic utilities
- `knowledge/` for specifications and design references
- `ops/` for deployment, monitoring and recovery
- `evidence/` for verification and provenance
- `brands/` for public identity/source-of-truth assets where appropriate

The result should read as a **professional engineering portfolio and operating estate**, not a folder of experiments.

## Control room

The reconciliation repository is the source of truth for consolidation work:

**[`estate-reconciliation`](https://github.com/angellllkr-eng/estate-reconciliation)**

It records duplicate evidence, canonical decisions, blockers, deployment-binding signals and preservation requirements.

### Operating protocol

**UNDERSTAND → PROTECT → EXECUTE → VERIFY → RECORD → HANDOFF → CONTINUE**

No archive/delete is called complete without platform confirmation. No production claim is made without runtime evidence.

## Current boundary

**PERSONAL ACCOUNT:** accessible and actively being organized.

**GITHUB ORGANIZATIONS:** organization membership/admin is not exposed by the currently connected GitHub account, so organization-side consolidation is **BLOCKED**, not guessed.

**PC FILESYSTEM:** arbitrary Windows folders are not exposed through the current connector. Uploaded source material remains preserved until a binary-capable migration path is available.
